01 What nHash is

A complete cryptocurrency written from scratch in C++: mining algorithm, blockchain, transactions, signatures, P2P network and pool — original, portable code, tested on real hardware (from a 2011 i5-2500K to a modern i7).

nHash is transparent (like Bitcoin, no Monero-style privacy) and designed to be fair for CPU mining. v2 of the algorithm fills its scratchpad with AES-NI (a single hardware instruction present on every x86 CPU since ~2010, equally fast on old and new) and mixes with a dual-lane, latency-bound loop of unpredictable branches — so it gains nothing from AVX2 or wide execution units. Measured on real hardware (i5-2500K vs i7-14650HX): a 2011 core stays within ~1.3× of a 2024 core, versus ~5-6× on RandomX — and under full multi-core load the old CPU is actually faster per core. Section 10 has the numbers.

Honest status

At the code level you have a complete engine, more advanced than most coins at launch. For a truly public network you still need real-world pieces (hosted seed nodes, an explorer, an audit) and, above all, real demand — see sections 14 and 15.

02 System components

Seven executables in the release folder. They read/write files from the directory you run them in (chain.dat, mempool.dat, peers.dat, <name>.wallet).

BinaryRole
nhashAll-in-one miner (what most people run). Name + password → creates the wallet, auto-detects the CPU, syncs a background node, mines to the pool with every core, live dashboard.
nhash-walletWallet: interactive menu (Dashboard + Transfer), plus CLI dashboard, transfer, address, balance, send, mine, info.
nhashdFull node: P2P network, peer discovery, sync, reorg, validation, optional internal mining, RPC. Run this on the host.
nhash-poolPool: many miners combine power, shares counted, proportional on-chain payouts. Runs on the host.
nhash-minerStandalone miner: connects to a node or pool over RPC and mines multi-threaded (advanced).
nhash-payPayment gateway: accept nHash for a product (single-address, unique-amount matching).
nhash-webBlock explorer (MoneroOcean-style): live network + pool stats, difficulty/block-time charts, supply & halving progress, clickable per-block detail (with transactions), and block / address lookup. Serves on the LAN.
Two roles

Creator/host: runs nhashd (seed) + nhash-pool, always on. Everyone else: just double-clicks nhash.exe — it finds the pool and the seed baked into the binary, no configuration.

04 Build from source

The code is portable. Use MSVC on Windows, g++ on Linux. Both produce functionally identical binaries (identical hashes — essential for consensus).

Windows (MSVC)

:: from the project folder — build_node.bat calls vcvars64 + cl
build_node.bat
:: output: build\nhash.exe, nhashd.exe, nhash-wallet.exe,
::         nhash-miner.exe, nhash-pool.exe, nhash-pay.exe

Linux (g++)

CORE="src/corehash.cpp src/block.cpp src/blockchain.cpp src/utxo.cpp \
      src/ed25519.cpp src/wallet.cpp src/storage.cpp src/params.cpp"
# -maes is required: the v2 scratchpad fill uses AES-NI
g++ -O2 -std=c++17 -maes -pthread -o nhashd       $CORE src/net.cpp src/daemon.cpp src/daemon_main.cpp
g++ -O2 -std=c++17 -maes -pthread -o nhash-wallet $CORE src/net.cpp src/cli.cpp
g++ -O2 -std=c++17 -maes -pthread -o nhash-miner  src/corehash.cpp src/block.cpp src/net.cpp src/miner.cpp src/miner_main.cpp
g++ -O2 -std=c++17 -maes -pthread -o nhash-pool   src/corehash.cpp src/block.cpp src/net.cpp \
      src/wallet.cpp src/ed25519.cpp src/params.cpp src/pool.cpp
g++ -O2 -std=c++17 -maes -pthread -o nhash        $CORE src/net.cpp src/daemon.cpp src/miner.cpp src/coremine.cpp
Verify

Crypto test suite: ed25519_test must print ALL TESTS PASSED (official RFC 8032 vectors). PoW self-tests live in avx2_attack, avx512_attack and latency_test — see section 10.

05 Run as creator (host: node + pool)

As creator you are the network anchor: an always-on seed node plus the pool that everyone mines to. Both live in a working directory that holds the chain and the pool wallet.

  1. Pick a working directory (chain.dat, pool wallet, logs live here).
  2. Create the pool wallet (it receives block rewards, then pays miners).
  3. Start the seed node, then the pool pointing at the node's RPC. Leave both running.
:: one-time: pool wallet (encrypted; password via COREHASH_PASS)
set COREHASH_PASS=your_long_password
nhash-wallet.exe newwallet poolwallet

:: seed node — listens on 9333, RPC on 9334, no peers ('-')
nhashd.exe 9333 -

:: pool — connects to the node RPC, listens for miners on 9350, share-shift 16
nhash-pool.exe 127.0.0.1:9334 poolwallet 9350 16

The node prints accepted block ... as blocks arrive; the pool logs shares, found blocks and payouts. On Linux run both with setsid nohup ... & so they survive logout (a systemd service is better for reboot-persistence).

Daemon arguments

nhashd <port> <peers|-> [mine_wallet] [threads] — use - for peers if you are the anchor; otherwise a comma-separated list (ip1:9333,ip2:9333). Omit the wallet to run a non-mining node (the usual choice for a seed that hosts a pool).

06 What miners run (zero config)

Everyone else just needs the release folder and a double-click. The pool and seed addresses are baked into the binary.

  1. Double-click nhash.exe.
  2. Pick a username and password (creates the encrypted wallet the first time).
  3. It auto-calibrates the thread count for the highest hashrate on that exact CPU (hybrid P+E cores and cache-limited chips aren't always fastest at 100% of threads), then connects to the pool, syncs a background node, and mines — live dashboard.

Earnings are split proportionally across all miners at each block (like Monero), so everyone earns fractions continuously. The dashboard shows your hashrate, your earnings (available + pending), height, difficulty and peers.

Override (optional)

A network.txt next to the exe overrides the default. First line: pool:host:port (a different pool), solo (a full node that mines whole blocks itself), or solo:host:port.

07 Wallet & keys

Keys are Ed25519. The address is blake2b(public_key), 64 hex chars. The wallet can be encrypted with a password (PBKDF2 + ChaCha20 + HMAC).

Double-click nhash-wallet.exe for the interactive menu (Dashboard + Transfer), or use it from the command line:

nhash-wallet.exe dashboard creator   # live panel: balance + earnings
nhash-wallet.exe address   creator   # show address — does NOT ask for the password
nhash-wallet.exe balance   creator   # show balance — does NOT ask for the password

The public key is stored in the clear, so address and balance are visible without a password. Only spending and mining (which need the secret key) ask for it. The dashboard is live when a node (nhash.exe) is running; otherwise it reads the local chain.

Backup

The <name>.wallet file is your money. Whoever has it (and the password, if encrypted) can spend your coins. Back it up offline.

Seed phrase (recommended): run nhash-wallet backup <name> to show a standard 24-word BIP39 phrase. Write it on paper and keep it offline — it is a full backup. Recover on any machine with nhash-wallet restore <name> (it asks for the 24 words, verifies the checksum so a typo is caught, and rebuilds the wallet). Anyone with the words can spend the coins, so never type them into a website or store them online.

COREHASH_PASS

For unattended runs (daemon, pool, scripts) set the COREHASH_PASS environment variable; otherwise the command asks for the password interactively, without echo.

08 Sending coins (Transfer)

Send to a hex address or to a local wallet name. The transaction is broadcast to the network through your running node and confirms in the next block.

In the wallet menu choose [2] Transfer and fill in the fields (each has an example): To (e.g. ana), Amount (e.g. 12.5), Memo (an optional note). Or from the CLI:

nhash-wallet.exe transfer creator <address_or_name> 12.5 "for GrgAI PRO"
# flat fee 0.001; change returns to you automatically
# nhash.exe must be running so the tx is broadcast
Memo

The memo is a local note, saved in transfers.log next to your wallet (your own record). Putting it on-chain would require a protocol change across all nodes; the coin transfer itself is fully on-chain.

Maturity

Freshly mined coins become spendable only after 100 blocks. Until then they show in the balance as "pending" but cannot be sent (standard anti-reorg rule).

09 Pool & external miner

The pool lets small miners combine power and be paid proportionally to their contribution (shares). In nHash this is the default path, so most people never touch these commands directly — nhash.exe does it for them.

Pool (on the host)

set COREHASH_PASS=pool_password
nhash-pool.exe 127.0.0.1:9334 poolwallet 9350 16
# args: <node_host:rpcport> <pool_wallet> <pool_port> [share_shift]

External miner (advanced)

nhash-miner.exe <host:port> <your_address_hex> <threads>
# point it at the pool (IP_pool:9350) or a node RPC (127.0.0.1:9334)

The pool receives the coinbase, counts each miner's shares and distributes proportionally. On-chain payouts happen automatically once a miner is owed a small threshold (~0.1 nHash) and the pool's coinbase matures (100 blocks). The last argument is the share shift — how much easier a share target is than the network target.

10 CPU fairness: the stress tests

The whole point of nHash is that an old CPU is not crushed by a new one. These are the actual attacks and measurements we ran against the algorithm, with numbers, not just claims.

Real cross-CPU fairness (measured on hardware)

The headline metric. v2 built identically (bit-for-bit test vector) on both machines, benchmarked single-thread and at full load:

i5-2500K (2011)i7-14650HX (2024)ratio
1 thread (per core)126 H/s~152–175 H/s~1.3×
all cores (total)152 H/s (4t)539 H/s (24t)3.5×
per core at full load38.0 H/s22.4 H/sold wins

Per core the 13-year gap is only ~1.3× (RandomX is ~5–6×). At full load the old CPU is actually faster per core: the 4 MB-per-hash working set means many-core CPUs starve their shared cache first (24 threads want 96 MB, the i7 has ~30 MB L3), so extra cores hit diminishing returns. The i7 leads on the total only by having 6× the cores — which is fair (a much bigger CPU should mine more). The 4 MB scratchpad is validated by this data: smaller would let many-core CPUs pull further ahead, larger would slow the old CPU's single thread.

Fill is no longer an attack surface (v1 → v2)

v1 filled the scratchpad with ChaCha8, a compute-bound phase that was 22% of a hash and vectorizable — modern CPUs sped it up with AVX2. v2 fills with AES-NI, one hardware instruction on every 2010+ CPU: now the fill is 5.6% of a hash and equally fast on old and new, so the AVX2 fill advantage is gone.

AVX2 attack — avx2_attack

Processes 4 nonces at once, one per AVX2 lane (the realistic miner optimization; the i5-2500K has only AVX1, so a big AVX2 win would be unfair). Output verified bit-identical to the reference hasher. Result on a modern i7, single thread:

VersionHashrateSpeedup
Scalar (reference)~139 H/s1.00×
AVX2 ×4~86 H/s0.62×

AVX2 is much slower. Why: the dual-lane loop needs two gathers and two scalar scatters per iteration (AVX2 has no scatter); each of the two data-dependent switch lanes forces SIMD to compute all four branches and blend; 64-bit multiply is emulated; and 4 scratchpads = 16 MB thrash the cache.

Latency-hiding — latency_test

The real GPU/ASIC question: they don't win with wider SIMD, they win by running many independent hashes at once to hide memory latency. This runs K interleaved streams on one core. Because a v2 hash already issues two reads at once (dual-lane), a single stream already uses much of the memory parallelism, leaving little for extra streams:

K streamsH/s totalper streamworking set
1147.6147.64 MB
2164.682.38 MB
3145.848.612 MB
4141.335.316 MB
6133.422.224 MB
8123.715.532 MB

Parallelism now helps only up to ~1.12× (K=2, down from v1's 1.23×) and drops below baseline by K=3. The real defense is memory capacity (4 MB/hash) + random-access bandwidth, not latency alone — which is exactly what makes it hostile to GPUs (thousands of threads × 4 MB × uncoalesced 8-byte reads).

AVX-512 — avx512_attack (ready to run)

The strongest CPU-SIMD attack: 8 nonces at once with AVX-512's native scatter, native 64-bit multiply (AVX-512DQ) and native variable rotate — the exact weapons AVX2 lacked. It is written, builds, and verifies bit-identical output; a CPUID guard makes it exit cleanly on machines without AVX-512 (most consumer Intel chips, which fuse it off), so it is safe to run anywhere and runs the real benchmark on Zen4/Zen5 or Xeon hardware. Prediction from the data: it also loses — 8 pads = 32 MB puts the working set deep in the thrash regime the latency test already mapped, and scatter only speeds the writes, which were never the bottleneck.

Verdict (v2)

AVX2 ✗ (0.62×), AVX-512 built & ready (expected ✗ — 32 MB working set), GPU ✗ (capacity + bandwidth). The fairness claim holds under measurement and v2 is stronger than v1 on every axis. It is not ASIC-proof (a chip with 4 MB SRAM per core is buildable), but no CPU coin is — and formal cryptanalysis/audit is still the honest prerequisite before real financial stakes.

11 RPC reference

The node RPC listens on 127.0.0.1:<P2P port + 1> (localhost only, for security). Simple text protocol, used by the miner and pool.

CommandResponseRole
getwork <addr>OK <target> <block>block template with coinbase to address
submit <block>OK <height>submit a solved block
sendtx <tx>OK <txid>relay a transaction (transfers, pool payouts)
getutxos <addr>OK <tip> <n> …unspent outputs of an address (balance, dashboard)
infoOK <height> <diff>chain state

The pool adds one command miners can call on the pool port: stats <addr> → OK <round_shares> <owed> <paid>, which powers the live "earnings" line.

Every item in this table is now done. 14 Path to public

From "friends with IPs" to "anyone downloads and joins automatically".

  1. Hardcoded seed nodes — put your 24/7 node IPs in g_params.seeds (params.cpp) and recompile. The binary finds the network on its own. (nHash already ships with the host seed baked in.)
  2. A dedicated 24/7 machine with a stable IP (a cheap VPS) for the seed + pool.
  3. Reachability beyond the LAN: a private-IP host only works on the same network. For remote friends without port forwarding, use a free tunnel (Cloudflare Tunnel, playit.gg) or a small VPS as a public seed.
  4. Block explorer + installers for Windows/Linux/Mac.
  5. Public testnet, then an announced fair launch (public date/time so everyone starts equal — no hidden premine).
  6. Security audit before any real financial stakes.
Real cost

These are no longer code: a VPS ~€5/month, time for a testnet, an expert for an audit. The code enables them; you operate them.

15 The truth about value

The part no serious person skips.

"mined − spent = profit" only becomes true after the coin has a price on a market. And price doesn't come from code, it comes from real demand: a stranger has to want to buy it. You cannot bootstrap value yourself — buying or mining your own coin is just moving money from one pocket to another.

Beware

The scheme "pump the price with my own trades to attract buyers, then sell" = pump-and-dump / rug pull. It is fraud, illegal, and steals from real people. A serious coin launches transparently: public code, no hidden premine, a real community.

The right question is not "how do I raise the price" but "why would a stranger want to hold this coin?". A good answer (utility, community, fair distribution) is what turns a solid technical experiment into a currency. For nHash, the first real utility is spending it on something you actually offer — for example buying GrgAI PRO with it.
